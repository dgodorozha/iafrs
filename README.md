# Institute for AI, Financial Risk and Stability

The site of the Institute, a non-profit research institute for artificial
intelligence, financial risk and stability. It takes its visual grammar from
the Institute's research material: white pages with dark panels, amber for
three letter codes and the active state, blue for data, one pixel rules, no
rounded corners and no shadows. Words are set in IBM Plex Sans and codes and
figures in JetBrains Mono, both self hosted under the SIL Open Font Licence.

The front page opens on a market tape: three synthetic markets that receive
the same shock, one of independent agents, one in which agents on a shared
model herd, and one in which a dynamic throttle engages. It is drawn on a
canvas from a seeded simulation (`js/site.js`), not from market data, and is
labelled as a demonstration.

The site is entirely static: five pages and a 404 page, a stylesheet, one small script, six
font files and a few images. There is no framework, tracker or third party
request, and it runs from this folder as it is.

```
iafrs/
├── index.html         Front page: the tape, what we do, support
├── research.html      A placeholder for now; the research sits on the Probatio page
├── probatio.html      The platform: the terminal, the research (three figures, method, limits, outputs), the problem, the evidence, a run, the controls
├── about.html         Mission, principles, structure, funding
├── support.html       A placeholder for now
├── 404.html           For a web host to show when an address does not exist
├── css/styles.css
├── js/site.js         Menu, and the market tape on the front page
├── fonts/             IBM Plex Sans and JetBrains Mono, with their licences
├── img/               Favicons and the Open Graph image
└── tools/
    ├── build.py       Generates the pages from one shared shell (see below)
    └── og.html        The Open Graph image, screenshotted to img/og.png
```

## Three things to fill in

At the top of `tools/build.py`:

- `EMAIL` is a placeholder (`contact@iafrs.org`) until the Institute has an
  address; it appears in the footer and on the support page.
- `PROBATIO_URL` is empty. Once the platform has a site of its own, put its
  address here and rebuild: the front page, the Probatio page and the footer
  gain a link to it.
- `SITE` is the address the site will live at, used only so that link
  previews find the Open Graph image.

Then run `python3 tools/build.py`.

A People page is written but switched off: set `PEOPLE_PAGE = True` in
`build.py`, put the photographs back under `img/people/` (the file names are
in `PEOPLE_LIST`) and rebuild to add it to the site and the navigation.

## Editing the pages

The pages are generated by `tools/build.py`, which holds the shared header and
footer once and the copy for each page as plain HTML strings. The three
figures in the research sections (the two rankings, the rules, the dose response)
are drawn as SVG from the tables at the top of the file, and each carries its
data table, so the chart and the table cannot disagree. Edit the copy or the
numbers there and run:

```
python3 tools/build.py
```

Editing the HTML files directly also works; the next run of the generator
will overwrite them.

## Viewing the site

Open `index.html` in a browser. Chrome does not load a site's own fonts when
a page is opened as a file, so to see it exactly as a visitor will, serve the
folder with the small web server built into macOS and open
<http://localhost:8080/>:

```
python3 -m http.server 8080 --directory ~/Downloads/iafrs
```

(Control-C in Terminal stops it.)

## Publishing on GitHub Pages

The site is set up for <https://dgodorozha.github.io/iafrs/>: `SITE` and
`BASE` in `build.py` hold that address and path, and the 404 page links from
them (every other page links relatively, so the folder also runs locally as
it is). Once, to set it up:

1. On GitHub, create a **public** repository named `iafrs`, with no README,
   licence or `.gitignore`.
2. From this folder, push it:

   ```
   cd ~/Downloads/iafrs
   git init -b main
   git add .
   git commit -m "Institute site"
   git remote add origin https://github.com/dgodorozha/iafrs.git
   git push -u origin main
   ```

3. In the repository, open *Settings > Pages*. Under *Build and deployment*,
   set *Source* to *Deploy from a branch*, the branch to `main` and the folder
   to `/ (root)`, and save.

A minute or two later the site is live. If it still shows GitHub's own 404
page after ten minutes, no Pages build has run yet; an empty commit starts
one: `git commit --allow-empty -m "Pages" && git push`.

After that, every change is published the same way: rebuild if you edited
`build.py`, then `git add .`, `git commit -m "…"` and `git push`. GitHub Pages
caches pages for up to ten minutes, so a private window shows changes soonest.

To give the Institute its own address later, enter the domain under
*Settings > Pages > Custom domain*, point its DNS at GitHub Pages as the page
instructs, then set `SITE` to the new address and `BASE` to `'/'` in
`build.py`, rebuild and push.

## The Open Graph image

`img/og.png` is a screenshot of `tools/og.html`, which reuses the stylesheet
and the tape. To regenerate it after a change, serve the folder and take a
1200 by 630 screenshot of the element `#shot` (Playwright's headless
Chromium, with reduced motion so that the tape is drawn complete).
